## Architecture and boundary decisions

The preserved dependency direction is:

```text
OceanMail → BEMPIC → M4P → DataLink
```

BEMPIC owns compact application representations, discovery/synchronization,
application byte budgets, persisted continuation, integrity verification, and
semantic application receipts. M4P continues to own addressing, routing,
store-carry-forward, network TTL, generic fragmentation, deduplication, and
cross-modality behavior. DataLink continues to own waveforms, FEC, ARQ, modem
timing, and physical-byte costs. The deterministic simulator models only the
opaque carrier contract and does not implement either lower layer.

The original generation-0 proof remains a behavioral oracle and is not a
normative wire format. The new `v01` module uses the merged specification's
full identity widths and semantics, while its implementation-local B1 framing
and codec ID remain explicitly experimental and unregistered. SHA-256 is used
only for deterministic content identity and corruption detection; it is not
authentication or confidentiality. The codec interface borrows DCCL's
useful *properties*—declarative bounds, maximum encoded size, fingerprints,
pluggability, and exact byte analysis—without a DCCL dependency or wire format.

Application authorization of a replacement source is supplied as an explicit
fact to BEMPIC; BEMPIC does not implement production authentication. The mock
M4P boundary accepts and returns one complete opaque BEMPIC record and does not
duplicate routing, fragmentation, TTL, retransmission, or DataLink behavior.
