## Design alternatives and boundary decisions

1. Replacing only the B1 envelope yields 98-byte generic capabilities and an
   84-byte generic summary. It does not meet either gate.
2. A static exact-profile capability alias plus the full-width compact summary
   yields the 75-byte cold exchange and preserves all capability fields. The
   same 69-byte full summary misses the warm gate by five bytes.
3. The first dynamic cache alias occupied three bytes and met the gate, but a
   receiver using the wrong checkpoint would interpret identical bytes as a
   different summary. That attempt was abandoned as a semantic failure.
4. Revision 2 therefore carries a full 32-octet binding:
   `SHA-256(domain || collection_id || U64BE(generation) ||
   U64BE(item_count) || collection_digest)`. Missing, stale, mismatched, or
   corrupted context fails before an operation is returned. The exact record
   is 35 bytes and still passes the warm gate.
5. Truncated identifiers, fingerprints, or cache bindings were rejected. A
   truncated hash would improve size but weaken the full-width collision
   boundary. Omitting negotiation or required operations was rejected as false
   accounting. Combining operations would change complete-operation framing.
6. Generic compression was not selected: these short records are dominated by
   full-width hash material, and a new dependency would not establish a tighter
   deterministic semantic proof.

The candidate uses header `0xb0 | operation_tag`, canonical unsigned LEB128
body length, and one canonical form byte. Generic records reuse the strict B1
operation content after its seven-byte envelope. Decoding checks the one-MiB
outer ceiling and exact body length before its only input-proportional bounded
allocation. Encoding is deterministic for `(record, explicit context)`, and
exact size is closed arithmetic without trial serialization.

The implementation-local codec ID `0xffff0001`, revision 2, is deliberately
private and nonconformant. The static alias reconstructs the full 32-octet
schema fingerprint and every other capability field. Cold summaries carry both
full 32-octet values. Revision 1 is retained only as an incompatible comparison
image. The specification registry was not modified.
